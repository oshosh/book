## 12.1 함수란
 - 함수는 일련의 과정을 문으로 구현하고 코드 블록으로 감싸서 하나의 실행 단위로 정의한 것

## 12.2 사용 이유
  - 코드의 재사용
  - 유지보수의 편의성과 신뢰성을 높이는 효과
  - 함수 내부를 읽지 않아도 되서 가독성 향상

## 12.3 함수 리터럴
  - 일반 객체는 호출 할 수 없지만 함수는 객체 타입의 값이며 호출 할 수 있다.
  - 함수는 식별자를 가져야 하며 함수 몸체 즉, 실행될 문들을 하나의 실행 단위로 정의한 코드 블록이다.
  - 함수 이름은 생략이 가능하며, 기명함수, 익명 함수가 있다.

## 12.4 함수 정의

### 함수 선언문
  - 함수 선언문은 함수 이름을 생략 할 수 없다.
    ```
    // Uncaught SyntaxError: Function statements require a function name
    function (x, y) {
      return x + y
    }
    ```
  - 기명 함수 리터럴을 단독으로 사용하면 함수 선언문으로 해석된다.
    ```
    // 함수 이름 생략 불가
    function foo () {
      return console.log('foo')
    }

    // 함수 리터럴을 피연자 사용시 표현식으로 해석되며 리터럴을 가리키는 식별자가 필요하다
    (function bar() {
      console.log('bar');
    });
    
    bar() // Uncaught ReferenceError: bar is not defined
    ```

### 함수 표현식
 - 함수 유효한 식별자만 호출할 수 있음
   ```
   // 기명 함수 표현식
   var add = function foo (x, y) {
     return x + y
   }
   console.log(add(2, 5))
  
   console.log(foo(2, 5)) // ReferenceError
   ```

### 함수 생성 시점과 함수 호이스팅
 - 함수 선언문과 함수 표현식은 생성 시점이 다르다. 함수 선언문이 끌어올려져 동작하는 것 처럼 호이스팅 발생
 - 함수 선언문 (함수 호이스팅 발생): 코드가 한 줄씩 순차적으로 실행되는 런타임(runtime) 이전에 자바스크립트 엔진에 의해 먼저 실행된다.
   -  런타임 이전에 이미 함수 객체가 생성되고, 함수 이름과 동일한 식별자에 할당까지 완료된다. 따라서 선언문 이전에 참조 및 호출이 가능하다.
 - 함수 표현식 (변수 호이스팅 발생): 변수에 할당되는 값이 함수 리터럴인 문이므로, 변수 선언문과 할당문을 한 번에 기술한 축약 표현과 동일하게 동작한다.
 - 변수 선언 자체는 런타임 이전에 실행되어 undefined로 초기화되지만, 함수 객체는 런타임(할당문이 실행되는 시점)에 평가되어 생성된다.

 ```
 // 함수 참조
 console.dir(add); // ƒ add(x, y)
 console.dir(sub); // undefined
 
 // 함수 호출
 console.log(add(2, 5)); // 7
 console.log(sub(2, 5)); // TypeError: sub is not a function
 
 // 함수 선언문 (함수 호이스팅 발생)
 function add(x, y) {
   return x + y;
 }
 
 // 함수 표현식 (변수 호이스팅 발생)
 var sub = function (x, y) {
   return x - y;
 };
 ```

## 12.6 참조에 의한 전달과 외부 상태의 변경

### 원시 값과 객체의 비교
 - 원시 타입 인수: 값 자체가 복사되어 전달된다. 함수 내부에서 매개변수 값을 변경(재할당)해도 원본은 훼손되지 않는다. (부수 효과 없음)
 - 객체 타입 인수: 참조 값(메모리 주소)이 복사되어 전달된다. 함수 내부에서 매개변수를 통해 객체를 변경하면 원본 객체가 직접 변경된다. (부수 효과 발생)
   ```
   function changeVal(primitive, obj) {
     primitive += 100; // 원시 값은 변경 불가능하므로 재할당을 통해 교체
     obj.name = 'Kim'; // 객체는 변경 가능한 값이므로 직접 변경
   }
   
   var num = 100;
   var person = { name: 'Lee' };
   
   changeVal(num, person);
   
   console.log(num);    // 100 (원본 유지)
   console.log(person); // { name: 'Kim' } (원본 훼손)
   ```

### 문제점과 해결 방법
 - 문제점: 객체의 변경을 추적하기 어려워지고 코드의 복잡성이 증가한다. 의도치 않은 상태 변경은 버그의 원인이 된다.
 - 불변 객체(immutable object) 사용
   ```
   const user = Object.freeze({
     name: 'Lee',
     age: 20
   });
   
   // 무시됨 (엄격 모드에서는 에러 발생)
   user.name = 'Kim'; 
   
   console.log(user.name); // 'Lee' (변경되지 않음)
   ```
 - 깊은 복사(deep copy)**를 통해 새로운 객체를 생성하고 재할당을 통해 교체
 - 순수 함수 사용
   ```
   const state = { count: 1 };

   // ✅ 순수 함수: 원본 state를 변경하지 않고 새로운 객체를 반환
   function increase(obj) {
     return {
       ...obj,           // 기존 속성 복사 (얕은 복사)
       count: obj.count + 1 // 변경하고 싶은 부분만 덮어쓰기
     };
   }
   
   const newState = increase(state);
   
   console.log(state.count);    // 1 (원본 보존)
   console.log(newState.count); // 2 (새로운 상태)
   ```
 - 옵저버 패턴: 객체 참조를 공유하는 모든 변경에 따라 추가 대응이 필요함.
   - vue2(Object.defineProperty), vue3(Proxy) 같은 경우 보통 사용
   - Object.defineProperty 경우 처음에 없던 속성을 나중에 추가하면 감시를 못 합니다. 그래서 Vue.set() 같은 API가 따로 필요
     - data()가 함수인 이유: 객체를 직접 리턴하면 컴포넌트 여러 개가 똑같은 '감시 대상 객체'를 공유
   - vue3의 Proxy 경우 원시 값을 { value: x }라는 객체 상자에 담습니다. 그래야 .value라는 속성이 생김
